# Mini NPU Simulator

십자가(Cross)와 X 형태의 숫자 배열을 비교하는 Python 콘솔 프로그램입니다. 두 필터와 입력 패턴의 같은 위치에 있는 수를 곱해서 더한 뒤, 더 높은 점수를 얻은 필터로 판정합니다.

## 실행 방법

Python 3.8 이상이 필요하며 별도 패키지 설치는 필요하지 않습니다.

1. `main.py`와 `data.json`을 같은 폴더에 둡니다.
2. 해당 폴더에서 터미널을 엽니다.
3. `python main.py`를 실행합니다. (`python`이 안 되면 Windows에서 `py main.py` 시도)
4. `1`은 3×3 직접 입력, `2`는 `data.json` 분석입니다.

직접 입력 모드에서는 필터 A, 필터 B, 패턴 순으로 각각 3줄씩 입력합니다. 각 줄에 공백으로 구분된 숫자 3개를 입력합니다. 예를 들어 십자가 모양은 아래와 같습니다.

```text
0 1 0
1 1 1
0 1 0
```

X 모양은 아래와 같습니다.

```text
1 0 1
0 1 0
1 0 1
```

잘못된 개수나 문자를 입력하면 그 행을 다시 입력하도록 했습니다. 직접 입력 모드에서 위의 십자가를 A, X를 B로 입력하고 X 패턴을 넣으면 A=1, B=5이므로 B로 판정됩니다.

## 구현 요약

- 배열은 Python의 2차원 리스트로 저장합니다. `matrix[row][col]`로 각 위치에 접근합니다.
- MAC 연산은 `mac()`에서 이중 `for`문으로 구현했습니다. 외부 계산 라이브러리는 쓰지 않았습니다.
- JSON 키 `size_N_idx`에서 N을 읽어 같은 크기의 필터를 선택합니다.
- JSON의 필터 키 `cross`와 정답 `+`는 `Cross`로, `x`는 `X`로 통일합니다.
- 두 점수의 차이가 `1e-9` 미만이면 `UNDECIDED`로 처리합니다. 동점인데 정답이 `Cross` 또는 `X`라면 FAIL입니다.
- JSON 필터와 패턴의 행·열·숫자 형식을 확인하고, 문제가 있으면 해당 케이스에 이유를 남깁니다.
- 성능 측정에는 `perf_counter()`를 사용하며 MAC 함수만 10번 호출해 평균을 계산합니다. 파일 읽기와 출력은 측정 구간에 넣지 않았습니다.

## 결과 리포트

첨부된 `data.json`을 그대로 사용한 실행 결과입니다. 평균 실행 시간은 실행하는 PC마다 달라지므로 고정된 값으로 적지 않았습니다.

| 항목 | 결과 |
| --- | --- |
| 전체 테스트 | 6개 |
| PASS | 3개 |
| FAIL | 3개 |

| 케이스 | 판정 | expected | 결과 |
| --- | --- | --- | --- |
| size_5_1 | UNDECIDED | X | FAIL |
| size_5_2 | Cross | Cross | PASS |
| size_13_1 | X | X | PASS |
| size_13_2 | UNDECIDED | Cross | FAIL |
| size_25_1 | UNDECIDED | X | FAIL |
| size_25_2 | Cross | Cross | PASS |

이번 데이터에서는 3개가 FAIL로 나왔습니다.
실패한 케이스는 `size_5_1`, `size_13_2`, `size_25_1`입니다.
세 경우 모두 두 필터의 점수가 같거나 차이가 매우 작아서 `UNDECIDED`가 나온 경우입니다.
예를 들어 `size_5_1`의 Cross 점수는 0.9이고 X 점수는 약 0.9입니다.
두 수를 그대로 `==`로 비교하면 작은 부동소수점 오차 때문에 서로 다르다고 판단할 수 있습니다.
그래서 `abs(score_a - score_b) < 1e-9` 조건으로 동점을 처리했습니다.
그 결과 실제 expected가 X 또는 Cross여도 동점이면 FAIL이 됩니다.
이 결과는 입력 데이터의 정답을 고쳐서 맞추기보다, 정해진 비교 규칙을 그대로 적용한 것입니다.
라벨도 JSON에 `+`, `x`, `cross`처럼 다르게 적혀 있으므로 비교 전에 통일했습니다.
라벨 정규화가 없다면 같은 십자가를 가리키는 `+`와 `Cross`가 서로 다른 값으로 취급될 수 있습니다.
행렬 크기가 틀리거나 필터가 빠진 경우는 데이터 형식 문제로 보고, 그 케이스만 FAIL로 기록합니다.
점수가 충분히 벌어졌는데도 예상 결과와 다르면 MAC 반복문의 인덱스 또는 필터 선택 로직을 점검해야 합니다.
반대로 점수 차이가 거의 없을 때는 부동소수점 표현과 동점 처리 기준을 먼저 확인해야 합니다.

### 연산 횟수와 시간 복잡도

| 크기 | 위치별 곱셈 횟수 |
| --- | ---: |
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

MAC은 N개 행을 순회하면서 각 행의 N개 열을 순회합니다. 따라서 곱셈 횟수는 N×N이며 시간 복잡도는 **O(N²)**입니다. 5×5에서 25×25로 커지면 위치별 연산은 25번에서 625번으로 25배가 됩니다. 실제 측정 시간은 반복문의 처리 비용이나 PC 상태 등의 영향을 받아 정확히 25배가 되지는 않습니다. 프로그램은 각 크기의 MAC을 10번 반복하고 평균 시간을 ms 단위로 출력합니다.

## 확인한 내용

- 직접 입력: 3×3 십자가와 X를 넣으면 점수 비교가 가능합니다.
- 잘못된 행 입력: 숫자 개수나 문자에 오류가 있으면 다시 입력할 수 있습니다.
- JSON 분석: 제공된 데이터 6개를 확인하고, PASS 3개와 FAIL 3개를 출력합니다.
- 데이터 형식 오류: 크기 불일치 등의 문제가 있어도 한 케이스의 FAIL을 기록하고 나머지 분석을 계속합니다.

※ JSON에 담긴 정답값이나 필터 점수를 프로그램에서 임의로 수정하지 않았습니다.
